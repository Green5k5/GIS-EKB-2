# Гибридный помощник KH WAY

Вопрос → быстрый разбор → при необходимости один вызов локальной LLM → проверка запроса → точный расчёт PHP → ответ и источники.

Активный обработчик: `ai/search.php` → `ai/hybrid.php`. Прежний диалоговый агент `native-agent.php` сохранён для сравнения, но не обслуживает интерфейс. Старый `query.php` используется только для нормализации слов и словарей; его прежний обработчик ответов не вызывается.

## Что работает

- Количество усадеб, фильтры по полу, поселению, основным сословиям, фамилии, имени и отчеству.
- Списки различных значений и частотность, средняя/медианная/суммарная/минимальная/максимальная площадь.
- Полный список значений поля улицы без прежнего ограничения в 15 строк.
- Несколько условий И, исключения через модель, числовые границы площади. Диапазон «от … до …» включает границы.
- Короткое «А в Уктусе?» после простого вопроса наследует операцию и остальные фильтры, заменяя поселение.
- Источники, условия запроса, маршрут обработки и время расчёта в интерфейсе.

Быстрый путь используется только при полном разборе вопроса. Нераспознанные слова отправляют вопрос модели. LLM возвращает JSON, ограниченный схемой; не считает и не пишет итоговую историческую справку. Сервер сохраняет явно распознанные условия ФИО, поселения, пола, основных сословий и границы площади независимо от ошибок модели. Дополнительные фильтры проверяются на происхождение из вопроса. Неподдержанные или неоднозначные запросы могут требовать уточнения; это не гарантия понимания произвольного русского текста.

Единственный реестр — `js/data-records.js`, 2569 записей. Одна запись означает усадьбу, не уникального человека. Одинаковые ФИО не доказывают тождество владельцев. Исторические написания улиц и описания местоположений сохраняются. Площади — саж²; неположительные/неизвестные площади исключаются из статистики и отмечаются отдельно. В поиске показаны первые 50 строк с явной отметкой ограничения; статистика всегда считается по всей выборке.

Пока не поддерживаются произвольные объединения ИЛИ, сравнения нескольких выборок и проценты. Сложные продолжения диалога требуют полного вопроса. При выключенной модели быстрые запросы продолжают работать.

## Локальная проверка Windows

Файлы моделей `models/*.gguf` и установленный движок `ai/llama-win-cpu-x64/` не входят в Git. На этой машине они сохранены и продолжают использоваться. На новой машине разместите рабочую модель в `models/qwen3-4b-iq3_m.gguf`, а CPU-сборку llama.cpp для Windows — в `ai/llama-win-cpu-x64/`. Лицензия и контрольные суммы модели хранятся в репозитории. Для Ubuntu нужен отдельный Linux-движок.

1. Запустите XAMPP/Apache и `ai/start-model.cmd`.
2. Откройте `http://kh-way/`, раздел «Инфографика».
3. Попробуйте «Сколько было мужчин?», «Какие есть улицы?», «Сколько усадеб с фамилией Петров?», «Средняя площадь усадеб купцов», «Сколько усадеб площадью от 100 до 200 в Уктусе?».
4. Для маршрута LLM: «Назови владельца наибольшего по площади участка в Уктусе», «Подскажи какие отчества у владельцев с фамилией Петров?», «Сколько усадеб не принадлежало купцам?».

`php ai/test-hybrid.php` проверяет быстрый маршрут, расчёты и сохранение условий. `php ai/test-hybrid.php --live` дополнительно обращается к работающему сайту и модели. Адрес сайта для live-теста можно задать переменной `KH_WAY_SITE_URL`. `php ai/test-agent.php` проверяет общий модуль вычислений. Старый `test-query.php` относится к прежнему поиску.

Модель: Qwen3-4B IQ3_M, файл 1 962 896 320 байт; сервер llama.cpp, только `127.0.0.1:8080`. Четыре CPU-потока, контекст 4096, один слот, без рассуждений в запросе. Установленный GGUF сохраняется, повторная загрузка не нужна. JSON-ответ ограничен 320 токенами; вызов модели — 60 секундами. На CPU модельный маршрут может занимать десятки секунд, особенно после запуска. Время показано в интерфейсе; оно не включает сетевую задержку и чтение реестра перед обработчиком.

## Ubuntu 24.04 LTS

Нужны PHP 8.1+ с cURL/mbstring и CPU-сборка `llama-server` с поддержкой JSON Schema. Запуск: `ai/start-model.sh`; пример службы — `ai/kh-way-ai.service.example`. URL модели переопределяется `KH_WAY_MODEL_URL`.

4 vCPU / 8 ГБ RAM — целевой профиль, но производительность зависит от конкретного CPU и конкуренции за ресурсы. Достаточность 10 ГБ диска нужно проверять с учётом ОС, сайта и журналов. На сервер переносите одну рабочую модель и Linux-движок; Windows DLL и экспериментальная 0.5B-модель не нужны. Для публичного сайта ограничьте частоту запросов к помощнику на веб-сервере; единственный CPU-слот не предназначен для большого количества одновременных сложных запросов.

Модель и данные остаются локальными. Лицензия Qwen — Apache 2.0; лицензии и контрольная сумма находятся в `models/`.

## Интерактивный ответ и карта

Ответ возвращает точные ID всей выборки. «Посмотреть на карте» открывает её целиком, заменяя прежние ручные условия, чтобы они не скрывали найденные записи. Затем обычные фильтры карты могут дополнительно сузить эту выборку. Плашка сверху показывает условия вопроса, число объектов на карте, возврат к ответу, обзор всей выборки и снятие фильтра. Снятие плашки сохраняет дополнительные ручные фильтры; общий «Сбросить» снимает всё.

В ответе доступны все найденные усадьбы: список загружается по 20 строк, поиск внутри него не меняет выборку карты. Нажатие на усадьбу сохраняет всю выборку и приближает конкретный участок с карточкой. Строки улиц/фамилий/других групп открывают соответствующее подмножество. Для min/max отдельно доступны участки с найденным экстремальным значением. Нулевой результат и уточнения не получают кнопок карты. Скачивание в помощнике отсутствует.

Исторические линии улиц также интерактивны: нажатие выбирает усадьбы по явным значениям поля street в Екатеринбурге и подсвечивает линию. Сокращённые формы подписи сопоставляются с названиями реестра. При неоднозначности или более существенном различии написания предлагается выбор; при отсутствии соответствия показывается пояснение, прежняя выборка сохраняется. Географическая близость не используется для приписывания усадеб улице. Проверка сопоставлений и обработки нажатия: `node tools/test-street-selection.cjs`.

Камера карты сохраняется при обычной фильтрации (сословие, пол, площадь, поиск), снятии условий и выборе линии улицы. Переход к единственному поселению происходит только при его включении; снятие поселения не перемещает карту. Обзор выборки и приближение конкретного участка выполняются явными кнопками перехода на карту. Проверка поведения камеры: `node tools/test-map-camera.cjs`.

## Отмена вопроса

Во время обработки есть кнопка «Отменить». Escape в поле вопроса также отменяет поиск. Текст сохраняется для исправления, отменённый ответ не попадает в историю, новый вопрос можно отправить сразу. Новый запрос через кнопку примера автоматически отменяет прежний.

PHP получает от модели поток SSE, собирает JSON-план и отслеживает отмену. Случайный 256-битный ID относится только к одному вопросу; отмена передаётся отдельным POST в `ai/cancel.php` и DELETE `/v1/stream?conv_id=...` на loopback llama.cpp. Процесс модели остаётся загруженным. Прерывание уже запущенного вычислительного пакета CPU может занять несколько секунд. Временные статусы ID находятся вне сайта в системном temp; вопросов и данных владельцев в них нет. Отмена перед стартом запроса тоже учитывается.

Для адресной остановки нужна версия llama.cpp с resumable streams и DELETE `/v1/stream` (локально проверено на установленной сборке 11320). Для PHP нужны два или более обработчика HTTP, чтобы отмена принималась одновременно с запросом: XAMPP/Apache и обычный PHP-FPM подходят; однопоточный `php -S` не подходит для этой проверки. Тест состояний и разборщика SSE: `php ai/test-request-control.php`.
