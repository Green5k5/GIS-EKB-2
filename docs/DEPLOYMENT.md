# Размещение карты и админки на Linux

Проекту нужен хостинг с Node.js 22.15+ (со встроенным `node:sqlite`), постоянно работающим процессом приложения и постоянным диском. Node.js раздаёт карту, таблицу, `/admin/`, API и тайлы. PHP и модель для этой версии не нужны. Для сайта выделите домен или поддомен, чтобы приложение открывалось с `/`.

## Первый запуск

1. По SSH склонируйте ветку `AI-admin-deploy` в каталог приложения вне публичного `document root`. Проверьте `node --version` и `npm --version`.
2. Создайте `.env` по образцу `.env.example` или укажите переменные в панели хостинга. Задайте `NODE_ENV=production`. Используйте свой `ADMIN_KEY` или оставьте пустым, чтобы скрипт создал новый ключ в `.env`. Для прокси на той же машине оставьте `HOST=127.0.0.1` и `PORT=3000`. Если хостинг сам задаёт порт и адрес прослушивания, используйте его настройки.
3. Если переносите свою коллекцию, сначала перенесите данные по инструкции ниже. Выполните `bash start.sh --setup-only`. Скрипт установит зависимости под Linux, подготовит SQLite и загрузит исходный реестр для новой базы.
4. Настройте постоянный запуск через панель хостинга или systemd. Приложение должно работать одним процессом, поскольку сессии админки хранятся в его памяти. Направьте весь трафик домена на приложение через HTTPS.

```bash
mkdir -p "$HOME/apps"
git clone --branch AI-admin-deploy --single-branch https://github.com/Green5k5/GIS-EKB-2.git "$HOME/apps/gis-ekb"
cd "$HOME/apps/gis-ekb"
```

Для проверки по SSH можно выполнить `bash start.sh` и остановить сервер через `Ctrl+C`. Пока он работает, в другой SSH-сессии выполните `curl -fsS http://127.0.0.1:3000/api/health`, подставив свой порт, если он отличается.

## Постоянный запуск через ispmanager

В разделе «Сайты» добавьте приложение Node.js или выберите этот обработчик для существующего сайта. Выберите Node.js 22.15+ и способ подключения «Порт». Используйте назначенный панелью `PORT`. Если версия Node.js в SSH отличается от настроенной для сайта, выполните подготовку через Shell-клиент проекта.

В параметрах запуска выберите `start` из `package.json` или задайте `npm start`. Если панель запрашивает файл запуска, укажите `server/server.js`. Убедитесь, что команда выполняется из каталога с `package.json`. Если панель скопировала проект в другой каталог, выполните `bash start.sh --setup-only` в копии, которую запускает панель. В настройках проекта укажите `NODE_ENV=production`, примените конфигурацию и включите HTTPS. Проверьте, что веб-сервер отправляет запросы в Node.js и не раздаёт каталог проекта напрямую.

Если обработчик Node.js недоступен в панели, уточните у хостера, поддерживает ли тариф постоянный Node.js-процесс с проксированием домена.

## Пример для VPS

Если HTTPS обслуживает Caddy на той же машине, направьте весь домен на Node.js. Замените `gis.example.org` своим доменом.

```caddyfile
gis.example.org {
	encode zstd gzip
	reverse_proxy 127.0.0.1:3000
}
```

При использовании другого прокси передавайте исходный заголовок `Host`. Админка сверяет его с `Origin` при изменении данных. В production браузер передаёт сессионные cookies по HTTPS.

Для постоянного запуска на Linux с systemd сохраните следующий пример как `/etc/systemd/system/gis-ekb.service`. Замените `gis-ekb`, `/srv/gis-ekb` и `/usr/bin/node` на пользователя, каталог и путь к Node.js на сервере. Пользователю службы нужны права записи в каталог базы, `data/uploads/` и `data/backups/`.

```ini
[Unit]
Description=GIS EKB web application
After=network.target

[Service]
User=gis-ekb
WorkingDirectory=/srv/gis-ekb
Environment=NODE_ENV=production
ExecStart=/usr/bin/node server/server.js
Restart=on-failure
UMask=0077

[Install]
WantedBy=multi-user.target
```

Выполните подготовку от имени пользователя службы, чтобы база и загруженные файлы принадлежали ему. После создания unit-файла выполните `sudo systemctl daemon-reload`, затем `sudo systemctl enable --now gis-ekb`. Логи доступны через `sudo journalctl -u gis-ekb -n 50`.

## Перенос существующей коллекции

Чтобы сохранить правки, черновики в базе и публикации, перенесите SQLite-базу и `data/uploads/`. Если нужны точки восстановления, перенесите и `data/backups/`. Эти каталоги и база исключены из Git. Незавершённые наборы импорта привязаны к пути исходной базы. Примените нужные наборы в мастерской до переноса.

Перед копированием остановите запись в базу и сделайте SQLite-копию, например командой `sqlite3 server/gis-ekb.sqlite ".backup gis-ekb.deploy.sqlite"`. При настроенном `DB_PATH` подставьте путь к используемой базе. Поместите копию на хостинге в `server/gis-ekb.sqlite` или по пути из `DB_PATH`. После переноса проверьте права записи для пользователя приложения.

Храните `.env`, SQLite, резервные копии и исходные загрузки вне публичного каталога. Направляйте запросы через Node.js, чтобы выдавались только предусмотренные приложением файлы. При обновлении кода сохраняйте рабочую базу и `data/`. После обновления запустите `bash start.sh --setup-only` и перезапустите процесс через панель хостинга или systemd.

## Проверка после запуска

- `/` открывает карту. Во вкладке «Данные» отображаются таблица усадеб и сообщение о работе над ИИ-помощником.
- `/api/health` отвечает `200`, а `/api/public/bootstrap` возвращает опубликованный реестр.
- `/admin/` открывается по HTTPS и принимает новый ключ.
- `/ai/status.php`, `/.env`, `/.git/HEAD` и `/server/gis-ekb.sqlite` отвечают `404`.
