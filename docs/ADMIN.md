# Мастерская карты

Открывается по адресу `/admin/`. Сайт запускается командой `npm start` (Node.js 22 или новее). Ключ берётся из `ADMIN_KEY` в `.env`; зависимости устанавливаются через `npm install`.

## Загрузка набора

1. «Загрузить данные» → выбрать папку, перетащить папку или выбрать отдельные файлы / ZIP.
2. Файлы накапливаются в общем перечне: их можно добавлять порциями и убирать по одному. «Загрузить файлы» сохраняет их на сервере без преобразования; загруженный набор переживает обновление страницы и перезапуск сервера. Нажать «Собрать карту», когда комплект готов. Предпросмотр ещё не меняет рабочие или опубликованные данные.
3. Проверить участки, найденные планы и сообщения о несовпадениях. Каждый план можно открыть отдельно на карте. Отметки определяют, какие планы добавятся; невыбранные можно удалить с сервера сразу.
4. «Добавить в коллекцию» сохраняет рабочую версию. «Опубликовать» делает её доступной посетителям.

Распознаются XLSX, XLS и CSV; контуры из комплекта SHP + DBF + PRJ (CPG используется для кодировки). SHX принимается вместе с комплектом. Проект QGIS QGZ позволяет прочитать настроенную связь с таблицей и видимость растров. Старые пути к файлам заменяются поиском по имени внутри загруженного набора.

В папке «Уктус» связь строится по номеру усадьбы; в примере Екатеринбурга — по колонке «Порядковый номер строки в таблице». Буквенные номера сохраняются. Неиспользованные колонки таблицы сохраняются в дополнительных сведениях, а исходные значения — отдельно от отредактированной карточки. Пол не угадывается по имени.

Общего ограничения 1,5 ГБ и ограничения 750 МБ на файл в ZIP нет. Загрузка идёт по файлам; ZIP распаковывается потоком на диск. Практический объём зависит от свободного места и ресурсов сервера. Поддерживаемые файлы показываются с назначением, размером и состоянием. Неподдерживаемые и служебные форматы (включая GeoPackage, VRT, AUX.XML и POINTS) не загружаются, их имена и причины пропуска показаны отдельно. JPG/PNG/WebP принимаются как планы для ручного размещения, даже если в папке уже есть GeoTIFF.

Ошибки отдельных строк не останавливают весь импорт. Необычная площадь сохраняется в исходных данных, числовое поле остаётся пустым, а карточка получает предупреждение. Повторы и строки без номера сохраняются отдельно под временными обозначениями. Повреждённый контур отмечается, остальные читаемые контуры и табличные строки сохраняются. Предупреждения видны после добавления в «Требует внимания»; исправление соответствующего поля снимает предупреждение, также сведения можно явно отметить проверенными.

## Старые карты

GeoTIFF в EPSG:3857 или EPSG:4326 с обычной привязкой без поворота автоматически превращается в WebP с максимальной стороной 4096 пикселей. Изображение и поля сохраняются целиком; автоматического удаления чёрного фона и обрезки нет. Местоположение читается из GeoTIFF. Для произвольных проекций и повёрнутых георастров сначала экспортируйте в QGIS подходящий GeoTIFF. Неуспешный растр показывается в предупреждениях, остальные данные можно добавить.

Обычные JPG, PNG и WebP загружаются через «Старые карты» → «Добавить изображение». Доступны указание центра на карте, масштаб, поворот, прозрачность и обрезка четырёх краёв. Обрезка не уничтожает оригинал подготовленного изображения. Совмещение по контрольным точкам и деформация изображения пока не реализованы.

## Редактирование

Нажмите на участок или строку списка. Основные поля видны сразу; семья, служба и дополнительные сведения раскрываются по необходимости. Значения категорий подсказываются по коллекции. Можно указать точку, нарисовать участок и перемещать вершины существующего контура. После изменения карточку нужно сохранить; для сайта требуется отдельная публикация.

Повторный импорт сопоставляет усадьбы по поселению и полному номеру. Ручные правки защищены по умолчанию. Принудительную перезапись можно включить в предпросмотре. Если данные менялись после проверки набора, применить устаревший результат нельзя — нужна повторная загрузка.

## Версии и резервные копии

Публикации содержат снимки данных, включая геометрию и настройки планов. «История публикаций» восстанавливает выбранную версию в рабочую карту и на сайт.

Перед импортом, очисткой и восстановлением создаётся полноценная SQLite-копия в `data/backups/`. Изображения лежат в `data/uploads/`; при резервировании сервера нужно сохранять обе папки вместе с основной базой `server/gis-ekb.sqlite` (или файлом из DB_PATH). Резервные копии и исходные загруженные файлы не доступны через публичные маршруты; посетителям отдаётся только подготовленный WebP.

«Начать с чистой карты» архивирует записи и контуры, убирает исторические слои и публикует пустую карту. Предыдущие публикации и загруженные изображения остаются для восстановления.

## Проверка

`npm test` запускает проверки разбора таблиц, сохранения буквенных номеров, разделения источников и примечаний, валидации контуров и полного цикла работы с отдельной тестовой базой: вход, ZIP, импорт, ручная правка, конфликт версий, публикация, очистка, копия и восстановление.
