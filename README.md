# ГИС Екатеринбург — карта и админка

## Запуск на Linux

Установите Node.js 22.15 или новее с npm. Из корня проекта запустите:

```bash
bash start.sh
```

Скрипт при необходимости установит зависимости и подготовит SQLite-базу. Он возьмёт `ADMIN_KEY` из окружения или `.env`. Если ключ отсутствует, скрипт сгенерирует его в `.env`. Пример остальных настроек — `.env.example`.

На машине, где запущен сервер, карта доступна по `http://127.0.0.1:3000/`, админка — по `http://127.0.0.1:3000/admin/`. Сервер работает в текущем терминале и останавливается по `Ctrl+C`. Для постоянного запуска на хостинге используйте панель приложения или службу. [Инструкция по размещению](docs/DEPLOYMENT.md).

ИИ-помощник временно отключён. [Материалы для разработки помощника](ai/README.md).

## Данные

В комплект входят **2 569 записей, 2 571 контур, три поселения, 21 исторический план, 56 объектов исторических слоёв и словарь**. Исходные файлы находятся в `js/data-records.js`, `js/data-polygons.js`, `js/map.js`, `js/layers.js`, файлах глоссария и `assets/`. Сохранены более поздние исправления данных и интерфейса из main.

Первый запуск переносит исходный набор в пустую SQLite-базу и создаёт первую публикацию. Повторный запуск сохраняет коллекцию и ручные правки. Намеренно очищенная карта с историей публикаций остаётся пустой.

Карта читает опубликованный снимок `/api/public/bootstrap`. После правок в админке нажмите «Опубликовать», чтобы обновить данные посетителей. Усадьбы, планы, исторические улицы, реки и крепость отображаются в мастерской. [Руководство админки](docs/ADMIN.md).

Рабочая база — `server/gis-ekb.sqlite` (можно переопределить через `DB_PATH`), изображения — `data/uploads/`, резервные копии — `data/backups/`. Сохраняйте их вместе при переносе отредактированной коллекции. Они, `.env`, зависимости и модель исключены общим `.gitignore`. Исходный набор первого запуска остаётся в Git.
